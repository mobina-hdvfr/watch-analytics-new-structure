# Media & Watch Analytics (ClickHouse)

محیط تحلیلی لوکال مبتنی بر **ClickHouse** برای ذخیره‌سازی، مدل‌سازی و تحلیل داده‌های مصرف محتوای رسانه‌ای؛ شامل تماشا و شنیدن فیلم، سریال، کتاب صوتی، موسیقی و سایر انواع محتوا در نرم‌افزارهای تلویزیون هوشمند.

این ساختار بازطراحی‌شده، محدودیت‌های مدل قبلی (که صرفاً بر فیلم و سریال متمرکز بود) را برطرف کرده و مدلی تعمیم‌یافته، ماژولار و مقیاس‌پذیر برای پشتیبانی از انواع محتوا و تحلیل‌های جمعیتی ارائه می‌دهد.

## ۲. پیش‌نیازها و راه‌اندازی سریع

### پیش‌نیازها

- **Docker** و **Docker Compose**
- **DBeaver** برای مشاهده و اجرای کوئری‌ها یا ابزار `clickhouse-client`

### راه‌اندازی کانتینر ClickHouse

ابتدا فایل متغیرهای محیطی را کپی کرده و رمز عبور را تنظیم کنید:

```
cp .env.example .env
```

سپس کانتینر را اجرا کنید:

```
docker compose up -d
```

برای بررسی وضعیت سرویس، دستور زیر را اجرا کنید:

```
curl http://localhost:8123/ping
```

خروجی مورد انتظار:

```
Ok.
```

### اتصال از طریق DBeaver

| مشخصه    | مقدار                                    |
| -------- | ---------------------------------------- |
| Host     | `localhost`                              |
| Port     | `8123` (HTTP) یا `9000` (Native)         |
| Database | `analytics`                              |
| Username | `analyst` (یا مقدار تنظیم‌شده در `.env`) |

## ۳. معرفی ساختار جداول (Data Dictionary)

### الف) جداول پایه (Lookup Dimensions)

**۱. جدول** `dim_media_type` **— انواع محتوا**

| شناسه (`type_id`) | نوع محتوا                        |
| ----------------- | -------------------------------- |
| 1                 | `movie` — فیلم                   |
| 2                 | `series` — سریال                 |
| 3                 | `tv_movie` — تله‌فیلم            |
| 4                 | `tv_series` — سریال تلویزیونی    |
| 5                 | `tv_mini_series` — مینی‌سریال    |
| 6                 | `episode` — قسمت سریال           |
| 7                 | `iran_tv_series` — سریال ایرانی  |
| 8                 | `football` — فوتبال              |
| 9                 | `audio_book` — کتاب صوتی         |
| 10                | `music` — موسیقی                 |
| 11                | `music_video` — موزیک ویدئو      |
| 12                | `podcast_series` — مجموعه پادکست |

**۲. جدول** `dim_age_rating` **— رده‌بندی سنی محتوا**

شامل رده‌های سنی `all`، `7+`، `13+` و `18+`.

**۳. جدول** `dim_province` **— استان‌ها**

شامل اطلاعات ۳۱ استان ایران با ستون‌های `province_id` و `name_fa`.

**۴. جدول** `dim_city` **— شهرها**

شامل اطلاعات شهرهای مرتبط با هر استان با ستون‌های `city_id`، `province_id` و `name_fa`.

### ب) جداول ابعادی و واقعیت (Dimensions & Fact)

- **جدول** `dim_media` **— اطلاعات محتوا**

  با استفاده از موتور `ReplacingMergeTree` ساخته شده و شامل اطلاعات کامل محتوا، از جمله عنوان فارسی و انگلیسی، خلاصه، مدت‌زمان محتوا بر حسب میلی‌ثانیه (`duration_ms`)، سال تولید، تاریخ انتشار، رده‌بندی سنی و نوع رسانه است.

  کلید مرتب‌سازی: `ORDER BY media_id`
- **جدول** `dim_user` **— اطلاعات کاربران**

  با استفاده از موتور `ReplacingMergeTree` ساخته شده و اطلاعات کاربران شامل شناسه کاربر (`user_id UUID`)، شماره تلفن، نام و نام خانوادگی، وضعیت حساب، زمان آخرین ورود و کلید جغرافیایی `place_id` را نگهداری می‌کند. این کلید برای اتصال به جدول `dim_city` استفاده می‌شود.
- **جدول** `fact_watch_log` **— رویدادهای تماشا**

  با استفاده از موتور `MergeTree` ساخته شده و اطلاعات مربوط به رویدادهای تماشا و مصرف محتوا را ذخیره می‌کند.
  - پارتیشن‌بندی ماهانه: `PARTITION BY toYYYYMM(created_at)`
  - کلید مرتب‌سازی: `ORDER BY (created_at, user_id)`
  - ستون‌ها: `watch_id`، `created_at`، `user_id`، `media_id` و `watched_ms`

## ۶. نکات فنی و قراردادها (Technical Notes & Conventions)

**۱. مدیریت مناطق زمانی (Timezones)**

تمام زمان‌های ثبت‌شده در لاگ‌ها با استاندارد `UTC` ذخیره می‌شوند. هنگام انجام تحلیل‌های زمانی، مقادیر موردنیاز به منطقه زمانی ایران (`Asia/Tehran`) تبدیل می‌شوند.

**۲. یکپارچگی واحدهای زمانی**

تمام فیلدهای زمانی مرتبط با مدت‌زمان محتوا و تماشا بر حسب میلی‌ثانیه ذخیره می‌شوند:

- `duration_ms`: مدت‌زمان کل محتوا
- `watched_ms`: مدت‌زمان تماشای محتوا

این یکپارچگی از خطاهای ناشی از تبدیل دقیقه، ثانیه و میلی‌ثانیه جلوگیری می‌کند.

**۳. فیلترهای پاک‌سازی داده‌ها (Data Cleaning Rules)**

- رویدادهایی که مدت‌زمان تماشای آن‌ها کمتر از صفر یا بیشتر از ۴ ساعت باشد، فیلتر می‌شوند تا خطاهایی مانند روشن ماندن تلویزیون و ثبت زمان غیرواقعی مصرف کنترل شوند.
- سقف منطقی مصرف ماهانه هر کاربر برابر با ۷۲۰ ساعت در نظر گرفته شده است.
